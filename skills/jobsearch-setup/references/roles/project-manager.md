# Ролевая вставка: менеджер проектов (IT, digital, внедрения)

Собрана на опыте реального поиска PM-роли. Добавляется к рыночному пакету страны.

## Что смотрит работодатель
- Какие проекты вёл от начала до конца: масштаб, сроки, команда, стейкхолдеры.
- Результаты: срок, бюджет, качество, рост команды или продукта — только то, что человек может защитить.
- Методы: где был настоящий Scrum/Kanban/водопад — честно. «Agile» в резюме у всех, разговор о реальной практике отличает.
- Инструменты: Jira, Confluence, MS Project и т. п. — различать «настраивал» и «пользовался».
- Предметная область: внедрения ERP/CRM, цифровизация процессов, разработка продукта — часто важнее общего «PM».

## Резюме
- Заголовок под тип вакансий (Projektmanager / IT Project Manager / Delivery Manager), не просто «менеджер».
- Пункты: проект → твоя роль → результат.
- Сертификаты (PMP, PRINCE2, Scrum) — часто ключевые слова для автоматических фильтров; указывать честно со статусом.

## Оценка вакансий — частые ловушки
- «Project Manager» в названии, а по задачам — продажи, ассистирование, чистый PMO-учёт или product management. Оценивать по задачам.
- Senior/Lead по задачам при скромном названии — проверять уровень по тексту.
- Отраслевой опыт как «обязательный» (стройка, финансы клиента, конкретная ERP) — жёсткий фильтр, не тратить письмо.

## Отбор
- Кейс-интервью (спланировать проект, разобрать конфликт, приоритизировать) — частый этап; готовить истории по формуле ситуация → действие → результат.
- В консалтинге — готовность к командировкам спрашивают первой.

## Смежные роли — расширение поиска
Delivery manager, implementation/rollout manager, process manager, consultant по внедрению, program coordinator, PMO (если человек не против), customer success для B2B-продуктов. Предлагать человеку, а не выбирать за него.

## Самые дешёвые шаги развития (для `jobsearch-growth`)
- Сертификат, который чаще всего встречается в вакансиях целевого рынка, — только если без него режут на автоматическом отборе.
- Пробные интервью на языке целевой страны по своим историям — часто самый сильный рычаг.
- Описать 1–2 своих проекта как кейсы (одна страница каждый) — пригодится и для писем, и для интервью.
