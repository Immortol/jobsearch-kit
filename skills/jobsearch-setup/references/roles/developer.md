# Ролевая вставка: разработчик

Добавляется к рыночному пакету страны. Копируется в правила человека разделом в `02_Documents` и `03_Strategy`.

## Что смотрит работодатель
- Стек и глубина: на чём писал в продакшене, а не «знаком».
- Код: GitHub или другой публичный код — 1–2 живых проекта с README важнее десятка учебных репозиториев.
- Масштаб: нагрузка, данные, размер команды, за что отвечал лично (архитектура, ревью, релизы, дежурства).
- Умение работать с AI-инструментами в разработке — уже ожидаемый навык.

## Резюме
- Навыки — группами: языки / фреймворки / данные / инфраструктура / инструменты. Без шкал «8 из 10».
- Пункты опыта: что построил, для кого, какой эффект (скорость, стабильность, деньги, время команды).
- Ссылки на GitHub и, если есть, на опубликованные проекты — в шапке.
- Ключевые слова стека из вакансии — там, где за ними есть реальный опыт.

## Отбор и собеседования
- Типичные этапы: техническое интервью (алгоритмы, системный дизайн, разбор кода), домашнее задание или лайвкодинг, разговор с командой.
- Подготовка — в `jobsearch-interview`: задачи по алгоритмам и системному дизайну вслух, разбор своих проектов.
- Большое бесплатное тестовое — можно предложить вместо него разбор своего проекта.

## Смежные роли — расширение поиска
Платформенная/DevOps-инженерия, данные (data engineering, аналитика), QA-автоматизация, интеграция AI-инструментов, встроенные системы, техническая поддержка с кодом, solutions engineer. Предлагать человеку, а не выбирать за него.

## Самые дешёвые шаги развития (для `jobsearch-growth`)
- Один показательный проект в новом стеке вместо курса.
- Вклад в открытый проект (даже документация и мелкие исправления — видны работодателю).
- Сертификаты облаков — только если их прямо требуют вакансии целевого рынка.
