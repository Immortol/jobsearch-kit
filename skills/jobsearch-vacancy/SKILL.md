# Вакансия → оценка → документы

Человек присылает вакансию. Ему нужно быстро понять, стоит ли подаваться, и получить готовые документы, а не лекцию. Ответ короткий; документы — файлами.

## Перед работой

Прочитай в проекте человека: `Rules/01_Facts.md`, `Rules/02_Documents.md`, `Rules/03_Strategy.md`, `Rules/04_Processes.md`, `Rules/Market_<код>.md` (рынка вакансии). Где лежат трекер, резюме и папки пакетов — в `04_Processes`, раздел «Где что лежит». Если правил нет — человек не прошёл настройку: оцени вакансию по тому, что он расскажет, и предложи `jobsearch-setup`.

Главные принципы (подробно — в правилах человека):
- В документы — **только факты из `01_Facts`**. Цифры — только из списка «готов защищать». Ничего не выдумывать.
- Недостающее **никогда не называть** в документах — ни прямо, ни намёком. Подавать через близкий реальный опыт.
- **Ничего не отправлять** от имени человека — только черновики.

## Шаг 1 · Уже было?

Проверь трекер (по компании, роли, ссылке). Если вакансия там есть — скажи одной строкой: статус, где пакет, что дальше. Не делай второй раз.

## Шаг 2 · Текст вакансии

Открой ссылку (WebFetch). Не открывается или за логином — попроси вставить текст. Сохрани суть вакансии в файл объявления (шаг 6): ссылка, компания, город/формат, условия, задачи, требования (обязательные / желательные), контакт, срок, как подавать.

## Шаг 3 · Способ подачи — до письма

Открой ссылку «откликнуться» и определи тип:
- **письмо человеку или простая форма** → пакет как обычно;
- **портал с аккаунтом без тестов** → пакет, в трекере пометка «портал с аккаунтом»;
- **онлайн-тест, видеоинтервью, длинная анкета** → письмо не писать; строка в трекере со статусом «Подготовлено» и пометкой «⚠️ тест/видео в портале — пакет по запросу»; человеку одной строкой. Пакет — если попросит;
- **только через агентство, закрыта или истёк срок** → без пакета, одной строкой почему.

Если вакансия есть и у работодателя, и у агентства — подавать напрямую работодателю.

## Шаг 4 · Оценка 1–5

По `03_Strategy`, раздел «Оценка вакансий». Главное правило: **оценивать по задачам**, а не по названию, отрасли компании или оформлению объявления.
- Сначала жёсткие отказы (обязательные требования, которых нет) — если есть, оценка 1–2, документов нет.
- Уровень по задачам, а не по названию: «Project Manager», который на деле продажи или ассистирование, — не его.
- Связи: если компания есть в списке связей/рекомендаций — пометка «🤝 <кто>»; сначала написать знакомому, потом подавать. Оценку это не меняет.
- Признаки быстрого найма (небольшая компания, контакт человека с почтой, «как можно скорее», простая подача) — пометка «⚡», если у человека есть срок.

**Ответ человеку — 3–5 строк**, не больше:
```
4/5 · <Компания> · <роль> · <город/формат> · <деньги, если указаны>
Почему: <одна строка>
Не хватает: <одна строка, или «всё есть»>
Резюме: мастер / адаптирую (<что меняется>)
Подача: <тип> · срок <дата>
```
3 и ниже — документы не делать, если человек сам не попросит.

## Шаг 5 · Документы (4–5 или по просьбе)

**Сопроводительное письмо** — если оно нужно на этом рынке (`Market_<код>`, раздел «Сопроводительное письмо»). Если на рынке письма почти не пишут — вместо него короткое сообщение рекрутеру/менеджеру (5–8 предложений) в чат, без PDF.

Как писать — по `02_Documents` и `references/letter.md`. Коротко:
- первое предложение — про позицию;
- один конкретный факт о компании **не из объявления** (найди поиском; у небольших компаний — особенно тщательно);
- 2–3 факта из `01_Facts`, которые закрывают задачи вакансии;
- обращение и тон — по нормам рынка;
- одна страница.

Сборка PDF — скриптами `scripts/` (Python + Playwright):
1. JSON письма по образцу в `scripts/make_letter.py` (данные отправителя — из `01_Facts`; фото — только если в `02_Documents` так решено).
2. `python3 scripts/make_letter.py letter.json letter.html`
3. `node scripts/render.mjs letter.html letter.pdf`
4. `python3 scripts/check_pdf.py letter.pdf` → должно быть `pages=1`. Больше — сократи текст (не шрифт ниже 10.5 pt). Посмотри страницу глазами (картинкой), если можешь.
Нет Playwright — собери письмо в Google Doc (скилл google-workspace) или .docx (скилл docx) и экспортируй в PDF.

**Резюме** — мастер из `02_Documents`, если акцент вакансии с ним совпадает. Адаптированная версия — только когда акцент реально сдвигается. Можно менять: заголовок, профиль (3–4 строки), порядок пунктов внутри мест работы, ключевые слова с реальным опытом за ними. Нельзя: даты, работодателей, цифры, должности.

## Шаг 6 · Пакет

Папка пакета — где сказано в `04_Processes` (Google Drive или папка на компьютере): `Applications/<Компания>/`. Отдельными файлами, по нормам рынка из `02_Documents` («Пакет документов»):
- `<Фамилия>_Letter.pdf` (или на языке рынка), `<Фамилия>_CV.pdf`, остальное — что просит работодатель;
- файл объявления `Vacancy_<Компания>_<Роль>.md` — рядом;
- склеивать в один PDF только если работодатель прямо требует.

## Шаг 7 · Трекер

Новая строка (колонки — по порядку из `04_Processes` / шаблона трекера): дата, компания, роль, источник, язык, статус «Подготовлено», следующий шаг (тип подачи, ссылка, срок; «⚠️ …», если нужно действие человека), оценка, размер компании, город, заметки (условия, чего не хватает, 🤝, ⚡), ссылка.

## Шаг 8 · Черновик письма (если подача по почте)

Только если в `04_Processes` разрешены черновики. Короткий текст по нормам рынка: позиция, что во вложении, при необходимости ответы на вопросы из объявления (зарплата — по правилу из `03_Strategy`, только если просят). Подпись — как в `02_Documents`. Вложения человек прикладывает сам (скажи, какие файлы).

## Итог человеку

```
Пакет готов: <папка>
Подать: <как и где> · до <срок>
<🤝 сначала написать <кто>, если есть>
```
Если сводка готовит много пакетов подряд — без вопросов, по правилам; всё спорное — одной строкой в сводке.
